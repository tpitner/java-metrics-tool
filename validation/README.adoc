= Validation Corpus
:toc: left
:toclevels: 2

Tento adresář obsahuje malý, ručně kontrolovatelný corpus pro validaci
`java-metrics` a externích providerů nad stejnými zdroji. Není to experimentální
dataset pro článek; jeho účelem je oddělit chybu adaptéru, rozdíl operační
definice a chybu samotného nástroje.

== Význam oracle

Oracle je předem stanovené očekávání, vůči kterému se posuzuje skutečný
výsledek. V corpusu má tři vrstvy:

* _build oracle_ říká, zda je případ sestavitelný;
* _subject oracle_ určuje, které logické typy musí provider najít a jednoznačně
  namapovat;
* _measurement oracle_ určuje očekávaný stav a hodnotu konkrétní metriky podle
  její explicitní operační definice.

Oracle proto není další metrics tool ani většinový názor několika nástrojů.
Hodnoty musí být odvozeny ručně nebo nezávislým postupem a zkontrolovány proti
zdrojovému kódu. Výstupy CK a CKJM-extended jsou důležité pro diferenciální
validaci, ale samy nejsou pravdou: neshoda může znamenat chybu našeho adaptéru,
chybu externího nástroje nebo legitimní rozdíl definic. Provider ve sloupci
`provider` váže očekávání ke konkrétní definici a brání tomu, aby se stejně
pojmenované, ale jinak počítané metriky zaměnily.

== Struktura

`cases.csv`::
Manifest případů. Určuje stabilní `case_id`, adresář Maven projektu,
zdrojový kořen, očekávaný výsledek kompilace a testovanou vlastnost.

`subjects.csv`::
Oracle adresovatelných typů. Provider-specific mapper musí každý uvedený typ
jednoznačně spojit se stejným logickým subjektem. Lokální a anonymní typy jsou
v corpusu přítomné, ale dokud nebude jejich mezitoolová identita zmrazena,
nejsou v tomto souboru požadovanými subjekty.

`measurements.csv`::
Ručně kontrolovaný oracle měření. Jeden řádek identifikuje případ, provider,
metriku, scope, subjekt, stav, vztah hodnoty a případnou hodnotu či meze.
První verze obsahuje přesné built-in počty členů. Řádky `ck.*` a `ckjm.*`
se doplní až po ručním výpočtu a klasifikaci definičních rozdílů; nesmějí být
odvozeny pouze opsáním výstupu testovaného nástroje.

`ck-exclusions.csv`::
Explicitní provider-specific výjimky ze subject oracle. Výjimka musí mít
důvod a test zároveň hlídá, zda nezastarala. První známou výjimkou je annotation
declaration, pro kterou připnutá verze CK nevydává řádek v `class.csv`.

`cases/<case-id>/`::
Samostatné malé Maven projekty bez externích závislostí. Každý případ má
vlastní `pom.xml`, aby jej bylo možné nezávisle sestavit a předat CK nebo
CKJM-extended.

== Případy

[cols="1,1,3",options="header"]
|===
|Case |Build |Účel

|`basic-members` |úspěch
|Prázdný typ a explicitní pole, konstruktory a metody.

|`inheritance` |úspěch
|Víceúrovňová dědičnost a více přímých potomků.

|`interfaces` |úspěch
|Interface inheritance, default metoda a implementující třída.

|`coupling` |úspěch
|Vazby mezi třemi balíky přes pole, konstruktor, návratový typ a volání.

|`overloads` |úspěch
|Přetížené metody a konstruktory se stejnou i různou aritou.

|`nested-types` |úspěch
|Static nested, inner, local a anonymous class.

|`modern-types` |úspěch
|Record, enum, annotation a sealed hierarchy v Java 17.

|`unresolved-dependency` |neúspěch
|Zdroj je syntakticky validní, ale chybí externí typ; source provider jej smí
analyzovat, bytecode provider musí vykázat nedostupnost místo tichého vyřazení.
|===

== Spouštění

Výchozí testy ověřují manifest, očekávaný build status, mapování subjektů a
built-in oracle:

[source,bash]
----
mvn test
----

`CkValidationCorpusTest` se spouští opt-in s připnutým standalone JARem. Již
teď spustí CK nad všemi případy, ověří mapování povinných type subjects a
provider-specific výjimky. Jakmile budou v `measurements.csv` řádky
`provider=ck`, stejný test začne porovnávat také jejich status, hodnotu a důvod:

[source,bash]
----
mvn test -Dtest=CkValidationCorpusTest \
  -Dck.jar=/absolute/path/to/ck.jar \
  -Dck.java=/absolute/path/to/jdk-21/bin/java
----

Maven zůstává na Javě 27. Parametr `ck.java` je povinný spolu s `ck.jar` a
vybírá podporovanou Java 21 JVM pouze pro externí CK proces; test nepřebírá
`java.home` Maven procesu.

Připnutá revize CK nyní vykazuje dvě explicitně kontrolovaná omezení: lokální
a anonymní typ mají jinou, dosud nezmrazenou mezitoolovou identitu a annotation
declaration nemá řádek v `class.csv`. Jakákoli jiná mapovací diagnostika test
ukončí chybou.

Ručně ověřený CK oracle nyní pokrývá type-level `ck.methods`,
`ck.public-methods`, `ck.fields`, `ck.public-fields`, `ck.dit` a `ck.noc` pro
všechny ostatní požadované typy a method/constructor-level `ck.parameters` pro
všechny stabilně adresovatelné explicitní členy. `ck.wmc`, `ck.rfc` a `ck.loc`
jsou ověřeny pro všech 61 stabilních type/method/constructor subjects. Další
validační skupinou jsou couplingové metriky.

Member subjects používají canonical zápis `owner#method(types)` nebo
`owner#<init>(types)`. Signatura rozlišuje overloady; pokud binding typu není
rozřešen, používá se syntakticky dostupné jméno místo domnělého FQN.

`ck.rfc` zde znamená počet unikátních method/super-method invocations, nikoli
tradiční response set. `ck.loc` znamená řádky normalizovaného AST textu, nikoli
fyzické řádky zdrojového souboru.

Budoucí `CkjmMetricsProvider` musí nejprve zkompilovat každý případ s
`expected_build=true`, analyzovat jeho `target/classes` se stejným classpath a
u `expected_build=false` publikovat `UNAVAILABLE`. Zdrojová revize, build
status, JDK, classpath, konfigurace provideru a hash JARu patří do provenance.

Built-in package oracle obsahuje také 55 ručně odvozených očekávání pro
`java.ca`, `java.ce`, `java.instability`, `java.abstractness` a
`java.distance`. Package subject je plně kvalifikované jméno balíku. Interval
využívá sloupce `lower` a `upper`; úplný report je v
`../docs/31-martin-validation-report.adoc`.

== Pravidla rozšiřování

* Jeden nový jev se přidává jako nejmenší samostatný případ nebo jako jasně
  zdůvodněné rozšíření stávajícího případu.
* Oracle se počítá ručně nebo nezávislým postupem; výstup měřeného provideru
  není sám sobě oraclem.
* Stejnojmenné metriky různých providerů se nesrovnávají bez kontroly
  operačních definic.
* Nekompilovatelný případ zůstává v corpus manifestu a v budoucím selection
  funnel; nesmí být odstraněn kvůli bytecode provideru.
